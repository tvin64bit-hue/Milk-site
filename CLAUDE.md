# Кафе «Милк» — сайт

Ознакомительный сайт кафе в Благовещенске. Заказы онлайн не принимаются — только звонок по телефону.

**Общайся со мной на русском.** Комментарии в коде — на русском.

## Источники истины

- `TZ-sayt-kafe-milk.md` — полное техническое задание. Всё, что не описано здесь, ищи там. **Перед началом каждого нового блока перечитывай соответствующий раздел ТЗ**, не работай по памяти.
- `menu.json` — единственный источник данных о меню. Ни одна цена, ни одно название блюда не должны быть захардкожены в коде или разметке.
- `Referens/` — исходные материалы: 89 фото блюд в `Referens/Menu`, 19 лайфстайл-фото и логотипы в `Referens/`. Папка только для чтения, обработанные картинки кладутся отдельно.

## Непреложные правила

1. **Никаких форм отправки данных.** Ни обратного звонка, ни подписки, ни чат-виджетов. Единственное поле ввода на сайте — поиск по меню.
2. **Фото блюда не выводится шире 480 px.** Исходники низкого разрешения — 540 px у большинства. На странице блюда фото стоит колонкой сбоку от текста, не во всю ширину.
3. **Тексты берутся из ТЗ дословно.** Не переписывай, не сокращай, не «улучшай». Если текста для блока нет — спроси, не сочиняй.
4. **Не выдумывай факты о кафе.** Цены, составы, вместимость зала, время работы — только из ТЗ. Пометки `[ЗАПОЛНИТЬ]` оставляй видимыми заглушками в вёрстке, не заменяй правдоподобными числами.
5. **Все цвета и размеры — через CSS-переменные** в одном файле. Хардкод hex-кодов в компонентах запрещён.
6. **91 страница блюд генерируется при сборке**, а не собирается в браузере. Иначе поисковики их не увидят.
7. **`prefers-reduced-motion: reduce` отключает весь параллакс, все сдвиги и бегущую строку.** Не опционально.
8. **Никакой серверной части.** Сайт собирается в статику и разворачивается на GitHub Pages / Netlify / Vercel.
9. **Горизонтальной прокрутки страницы не должно быть** ни на одном размере экрана от 320 px.
10. **Проверять не только `scrollWidth`, но и выход элементов за границы вьюпорта.** `overflow-x: hidden` на `body` прячет переполнение, и сломанная вёрстка выглядит исправной: так на 390 px кнопка меню уехала за правый край и стала недоступной, а проверка прокрутки этого не увидела. Обходить элементы и сравнивать их `getBoundingClientRect()` с шириной документа
11. **Тени не темнее `rgba(61,43,28,0.10)`.** Тяжёлые тени ломают акварельную лёгкость концепции.

## Чего в этом дизайне быть не должно

Чёрно-красной гаммы и иероглифов. Стоковых фотографий. Таймеров обратного отсчёта и всплывающих окон со скидкой. Каруселей с автопрокруткой на первом экране. Градиентов из трёх и более цветов. Смеси фирменных дудлов со сторонними наборами иконок.

Это сайт кафе с завтраками и кофейней, а не витрина доставки суши. Если решение выглядит как типовой лендинг доставки — оно неверное.

## Работа с изображениями

- **Фон новых снимков блюд — бежевый, деревянный или фирменная подложка.** Чисто-белый и чёрный фон под блоб-маску не годятся: белый растворяет форму блоба и оставляет дырку в сетке, чёрный даёт тёмное пятно. Таких кадров 10 из 88, они правятся на сборке, но это лечение симптома — список на пересъёмку печатает `node scripts/otchet-fon.mjs`
- **Фон разбирается по двум независимым признакам — яркости и цветности.** Смешивать их нельзя: кадры со своего бежевого кресла, снятые темнее или с другим балансом белого, тогда уезжают в брак вместе со стоковой съёмкой. Цветность — разница красного и синего каналов углового фона: у кресла от +6 до +32, у предметной съёмки около нуля
- **Кадры со своего фона нормализуются к эталону** — угловому фону `shakshuka`. Баланс белого и экспозиция — две разные операции: баланс идёт множителями по каналам, нормированными так, чтобы яркость не менялась, экспозиция — гамма-кривой с потолком 12 %. Одним множителем делать нельзя: линейное умножение поджимает насыщенность к белому и лосось желтеет
- **Правка снимка проверяется по еде, а не по фону.** Портится именно еда. Область блюда — крупнейшая связная зона с насыщенностью выше 40 % — меряется до правки и дальше не пересчитывается: если отбирать пиксели порогом заново, набор точек меняется и сравнение теряет смысл. Пороги: тон ≤ 3°, падение насыщенности ≤ 5 пунктов, изменение яркости ≤ 8 %. Не прошедший кадр правится ослабленно или не правится вовсе. Отчёт: `node scripts/otchet-pravki.mjs`
- **Подъём тёмной точки применять нельзя:** он делает снимок мутно-серым, на тёмном сланце это уже проверено
- Исходники в `Referens/` не трогать и не переименовывать. Обработанные версии складывать в `public/images/`.
- Имя файла блюда = поле `id` из `menu.json`. Например `shakshuka.webp`.
- Обрезка под квадрат берётся из поля `crop`: `top`, `center`, `bottom`. У 28 позиций стоит `top` — это карточки с вшитым в картинку текстом внизу, его надо срезать.
- WebP с JPEG-запасом, `width`/`height` заданы, `loading="lazy"` для всего ниже первого экрана.

## Как работать

- Делай блоками, а не всё сразу. После каждого крупного куска — короткий отчёт, что готово и что дальше.
- Не устанавливай тяжёлые библиотеки анимации. Параллакс — на `IntersectionObserver` и `requestAnimationFrame`.
- Если ТЗ противоречит само себе или чего-то не хватает — **спроси, не додумывай**.

## Стек

Astro в режиме статической генерации, sharp для изображений, обычный CSS с переменными, ванильный JS. Никаких UI-фреймворков и библиотек анимации. Разворачивается на GitHub Pages из ветки `main` через `.github/workflows/deploy.yml`.

Адрес сайта: `https://tvin64bit-hue.github.io/Milk-site`. Из-за подкаталога **все внутренние ссылки и пути к файлам собираются через `put()`** из `src/lib/put.ts` — прямые пути вида `/menu` сломаются.

## Команды

- Установка: `npm install`
- Изображения: `npm run images` — готовит `public/images/` из `Referens/`. Запускать после изменения снимков; папка в гит не коммитится
- Разработка: `npm run dev`
- Сборка: `npm run build`
- Просмотр сборки: `npm run preview`
- Проверка данных: `npm run check:menu`
- Контрольный лист обрезки брендированных карточек: `node scripts/probe-crop.mjs`

## Где что лежит

- `menu.json` — все 91 позиция. Сгенерирован из раздела 10.6 ТЗ скриптом `scripts/generate-menu.mjs`; после генерации источник истины — сам файл
- `src/lib/menu.ts` — чтение меню, форматирование цен, alt и описания
- `src/lib/kafe.ts` — адрес, телефон, режим работы, навигация. Всё из ТЗ, выдумывать нельзя
- `src/styles/tokens.css` — единственное место с цветами и размерами
- `scripts/granica-teksta.mjs`, `scripts/obrezka.mjs` — срезание вшитой в фотографию подписи у брендированных карточек
