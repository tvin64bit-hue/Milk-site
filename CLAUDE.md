# Кафе «Милк» — сайт

Ознакомительный сайт кафе в Благовещенске. Заказы онлайн не принимаются — только звонок по телефону.

**Общайся со мной на русском.** Комментарии в коде — на русском.

## Источники истины

- `TZ-sayt-kafe-milk.md` — полное техническое задание. Всё, что не описано здесь, ищи там. **Перед началом каждого нового блока перечитывай соответствующий раздел ТЗ**, не работай по памяти.
- `TZ-prilozhenie-foto.md` — приложение к ТЗ про фотографии: отложенное решение о форме кадра, список из десяти позиций на пересъёмку, требования к съёмке и порядок замены файла. Читать вместе с разделами 3 и 9 основного ТЗ
- `menu.json` — единственный источник данных о меню. Ни одна цена, ни одно название блюда не должны быть захардкожены в коде или разметке.
- `Referens/` — исходные материалы: 89 фото блюд в `Referens/Menu`, 19 лайфстайл-фото и логотипы в `Referens/`. Папка только для чтения, обработанные картинки кладутся отдельно.

## Непреложные правила

1. **Никаких форм отправки данных.** Ни обратного звонка, ни подписки, ни чат-виджетов. Единственное поле ввода на сайте — поиск по меню.
2. **Фото блюда не выводится шире 480 px.** Исходники низкого разрешения — 540 px у большинства. На странице блюда фото стоит колонкой сбоку от текста, не во всю ширину.
3. **Тексты берутся из ТЗ дословно.** Не переписывай, не сокращай, не «улучшай». Если текста для блока нет — спроси, не сочиняй.
4. **Не выдумывай факты о кафе.** Цены, составы, вместимость зала, время работы — только из ТЗ. Пометки `[ЗАПОЛНИТЬ]` оставляй видимыми заглушками в вёрстке, не заменяй правдоподобными числами.
5. **Все цвета и размеры — через CSS-переменные** в одном файле. Хардкод hex-кодов в компонентах запрещён.
6. **Архитектура сменилась на PHP** (блок A). Каталог, 91 страница блюда, главная и 404 собираются на лету — `sayt/index.php` читает `sayt/dannye/menu.json` при каждом запросе, а не при сборке. Поисковики видят готовый HTML так же, как раньше: разница внутренняя, в разметке страницы её не видно.
7. **`prefers-reduced-motion: reduce` отключает весь параллакс, все сдвиги и бегущую строку.** Не опционально.
8. **Серверная часть теперь есть — это осознанное решение**, а не нарушение прежнего правила. Причина: `/admin` должна писать `menu.json` на сервере, а статика этого не умеет. Сайт больше не публикуется на GitHub Pages — только выгрузкой файлов на sweb.
9. **Горизонтальной прокрутки страницы не должно быть** ни на одном размере экрана от 320 px.
10. **Проверять не только `scrollWidth`, но и выход элементов за границы вьюпорта.** `overflow-x: hidden` на `body` прячет переполнение, и сломанная вёрстка выглядит исправной: так на 390 px кнопка меню уехала за правый край и стала недоступной, а проверка прокрутки этого не увидела. Обходить элементы и сравнивать их `getBoundingClientRect()` с шириной документа
11. **Узкое окно браузера — не телефон.** Настоящий телефон расширяет область раскладки под содержимое, и `position: fixed` шапка растягивается вместе с ней: правый край с кнопкой меню уезжает за экран, а страница ездит вбок. В окне 390 px этого не видно. Поэтому `npm run check:verstka` гоняет три устройства через эмуляцию и сверяет `innerWidth` с `clientWidth` — их расхождение и есть признак раздутой раскладки
12. **Предок с `overflow` обрезает потомка не всегда.** Для `position: absolute` он должен быть ещё и containing block, то есть сам позиционирован. Прокручиваемая лента без `position: relative` не обрезала подписи для скринридеров внутри карточек, и самая правая растягивала документ до 2304 px при экране 390
13. **Тени не темнее `rgba(61,43,28,0.10)`.** Тяжёлые тени ломают акварельную лёгкость концепции.

## Чего в этом дизайне быть не должно

Чёрно-красной гаммы и иероглифов. Стоковых фотографий. Таймеров обратного отсчёта и всплывающих окон со скидкой. Каруселей с автопрокруткой на первом экране. Градиентов из трёх и более цветов. Смеси фирменных дудлов со сторонними наборами иконок.

Это сайт кафе с завтраками и кофейней, а не витрина доставки суши. Если решение выглядит как типовой лендинг доставки — оно неверное.

## Работа с изображениями

- **Форма кадра переключается токенами в `tokens.css`,** правок в компонентах не требует. Пар две, потому что решения разные: `--kadr-maska` — фотографии блюд, владелец выбрал прямоугольник со скруглением, блоб срезал края круглой посуды; `--kadr-maska-layf` — лайфстайл-кадры, там остался блоб, срезается только фон
- **Глубина блоба задаётся `MYAGKOST` в `scripts/blob.mjs`.** Ноль — формы, утверждённые в блоке 1; единица — почти круг. Стоит ноль: смягчение вводилось ради еды, а еда теперь в прямоугольнике. Посмотреть другой вариант, не трогая файл: `BLOB_MYAGKOST=0.55 npm run build`
- **Фон новых снимков блюд — бежевый, деревянный или фирменная подложка.** Чисто-белый и чёрный фон под блоб-маску не годятся: белый растворяет форму блоба и оставляет дырку в сетке, чёрный даёт тёмное пятно. Таких кадров 10 из 88, они правятся на сборке, но это лечение симптома — список на пересъёмку печатает `node scripts/otchet-fon.mjs`
- **Фон разбирается по двум независимым признакам — яркости и цветности.** Смешивать их нельзя: кадры со своего бежевого кресла, снятые темнее или с другим балансом белого, тогда уезжают в брак вместе со стоковой съёмкой. Цветность — разница красного и синего каналов углового фона: у кресла от +6 до +32, у предметной съёмки около нуля
- **Кадры со своего фона нормализуются к эталону** — угловому фону `shakshuka`. Баланс белого и экспозиция — две разные операции: баланс идёт множителями по каналам, нормированными так, чтобы яркость не менялась, экспозиция — гамма-кривой с потолком 12 %. Одним множителем делать нельзя: линейное умножение поджимает насыщенность к белому и лосось желтеет
- **Правка снимка проверяется по еде, а не по фону.** Портится именно еда. Область блюда — крупнейшая связная зона с насыщенностью выше 40 % — меряется до правки и дальше не пересчитывается: если отбирать пиксели порогом заново, набор точек меняется и сравнение теряет смысл. Пороги: тон ≤ 3°, падение насыщенности ≤ 5 пунктов, изменение яркости ≤ 8 %. Не прошедший кадр правится ослабленно или не правится вовсе. Отчёт: `node scripts/otchet-pravki.mjs`
- **Подъём тёмной точки применять нельзя:** он делает снимок мутно-серым, на тёмном сланце это уже проверено
- **Фон первого экрана — `Referens/hero-fon.png`,** акварельная текстура с вшитыми дудлами. Своей фотографии на первом экране нет, слой `DudlyFona` там не ставится: нарисованные бутылка, круассаны, чашка, вафля и печенье уже внутри картинки. Текст стоит в левой трети, где фон ровный и светлый
- **Фон правится только по средним тонам.** Они уходят в персиковый и тянутся к `--beige`; света остаются молочными и не трогаются вовсе. Баланс белого, применённый ко всему кадру, сажает средние тона точно, но уводит подложку в зелень — поэтому правка взвешивается по яркости пикселя и гаснет до начала светов. Сила подбирается сама: цена считается по двум точкам (средние тона к `--beige`, света к `--milk`), падение насыщенности ограничено десятой частью. Отчёт печатает `npm run images`
- Исходники в `Referens/` не трогать и не переименовывать. Обработанные версии складывать в `public/images/`.
- Имя файла блюда = поле `id` из `menu.json`. Например `shakshuka.webp`.
- Обрезка под квадрат берётся из поля `crop`: `top`, `center`, `bottom`. У 28 позиций стоит `top` — это карточки с вшитым в картинку текстом внизу, его надо срезать.
- WebP с JPEG-запасом, `width`/`height` заданы, `loading="lazy"` для всего ниже первого экрана.

## Как работать

- Делай блоками, а не всё сразу. После каждого крупного куска — короткий отчёт, что готово и что дальше.
- Не устанавливай тяжёлые библиотеки анимации. Параллакс — на `IntersectionObserver` и `requestAnimationFrame`.
- Если ТЗ противоречит само себе или чего-то не хватает — **спроси, не додумывай**.

## Стек

Два слоя, и это важно понимать перед правкой.

**Слой дизайна** — прежний, на Astro: `src/` целиком, `sharp` для изображений, обычный CSS с переменными, ванильный TypeScript. Здесь по-прежнему живут исходники стилей, компонентов, дудлов и форм блоба — это авторский источник дизайна, и он не выброшен.

**Слой публикации** — `sayt/`, на PHP 8.2+. Разметку `sayt/vidy/*.php` пишут руками, а вот стили и графику — нет: `npm run sayt` вычитывает их из `src/` и кладёт готовыми в `sayt/statika/sayt.css` и `sayt/app/grafika.php`. **Любая правка палитры, шрифтов или дудлов делается в `src/`, а не в `sayt/statika/`** — файл там перезаписывается при следующей сборке и ручная правка потеряется.

Разворачивается не через GitHub Pages, а обычной выгрузкой содержимого `sayt/` на хостинг sweb, в подкаталог `/milk-site`. Адрес сайта и подкаталог — в `sayt/app/konfig.php`, константа `BAZA`. Из-за подкаталога **все внутренние ссылки и пути к файлам собираются через `put()`** из того же файла — прямые пути вида `/menu` сломаются.

Админка — `sayt/admin/`, вход по паролю на `/admin`. Пишет `sayt/dannye/menu.json` прямо на сервере: там теперь и живут актуальные цены после публикации, отдельно от `menu.json` в корне репозитория.

## Команды

- Установка: `npm install`
- Изображения: `npm run images` — готовит `public/images/` из `Referens/` и попутно `sayt/images/`. Запускать после изменения снимков; обе папки в гит не коммитятся
- Разработка дизайна (Astro): `npm run dev` / `npm run build` / `npm run preview`
- Сборка PHP-статики из дизайна: `npm run sayt` — пересобирает `sayt/statika/sayt.css` и `sayt/app/grafika.php` из `src/`. Запускать после любой правки стилей или дудлов
- Локальный PHP-сервер: `npm run sayt:server` — поднимает встроенный сервер PHP на `sayt/` с той же подпапкой `/milk-site`, что на хостинге
- Проверка данных: `npm run check:menu`
- Проверка целостности PHP-страниц: `npm run check:php` — обходит все 95 адресов, требует, чтобы каждый дошёл до `</html>` и чтобы `sayt/dannye/oshibki.log` остался пустым. Требует запущенного `npm run sayt:server`
- Проверки вёрстки, фона, SEO: `npm run check` — те же скрипты, что и раньше, принимают адрес вторым аргументом и одинаково проверяют что Astro-версию (`npm run preview`), что PHP-версию (`npm run sayt:server`)

## Где что лежит

- `menu.json` (корень) — исходная копия для новой выгрузки. `sayt/dannye/menu.json` — рабочая копия на сервере, её правит админка; после первой публикации это два независимых файла, синхронизировать вручную
- `src/lib/menu.ts` / `sayt/app/menu.php` — чтение меню, форматирование цен, alt и описания. Второе — порт первого на PHP, при правке логики менять оба
- `src/lib/kafe.ts` / `sayt/app/kafe.php` — адрес, телефон, режим работы, навигация. Всё из ТЗ, выдумывать нельзя
- `src/styles/tokens.css` — единственное место с цветами и размерами для обоих слоёв
- `sayt/admin/` — панель `/admin`: вход (`app/dostup.php`), проверка и запись меню (`app/hranenie.php`), приём и обрезка фото (`app/foto.php`)
- `scripts/granica-teksta.mjs`, `scripts/obrezka.mjs` — срезание вшитой в фотографию подписи у брендированных карточек. Работают только в конвейере Node — админка снимки без подписи не срезает, это для новых кадров
