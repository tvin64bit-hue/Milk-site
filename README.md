# Сайт кафе «Милк»

Ознакомительный сайт кафе в Благовещенске. Заказы онлайн не принимаются —
только звонок по телефону.

Эта инструкция написана для человека, который не программист. Правка меню —
через панель управления в браузере, без каких-либо технических знаний.

---

## Главное, что нужно знать

Всё меню — цены, составы, фотографии, наличие — правится через панель
управления на странице **`/admin`** вашего сайта. Правка видна на сайте
**сразу**, без ожидания и без отдельных действий.

Сайт — обычные файлы на хостинге sweb, не на GitHub. Публикация — это
выгрузка папки `sayt/` на сервер, а не «сборка» и не «Actions». Дальше
объясняется, что где лежит и как всем этим пользоваться.

---

## Вход в панель управления

Откройте `https://ваш-сайт/milk-site/admin/` (адрес зависит от того, где
выгружен сайт — уточните у того, кто выгружал).

**В первый раз** сайт сам покажет страницу «Первая настройка» — на ней
задаётся логин и пароль. Пароль нигде не хранится в открытом виде: сервер
запоминает только его отпечаток, из которого сам пароль не восстановить.
Страница настройки открывается только один раз — после сохранения пароля
она сама закрывается.

**Забыли пароль?** Через файловый менеджер хостинга найдите и удалите
файл с именем вида `dostup-....php` — он лежит либо в папке `dannye/`
рядом с сайтом, либо в отдельной папке `milk-dostup` на уровень выше
папки сайта на сервере (это зависит от настроек хостинга, определяется
автоматически при первой настройке). После удаления файла страница
первой настройки откроется снова, и можно задать новый пароль. Само меню
при этом не пострадает — файл с паролем и файл с меню разные.

После пяти неверных попыток входа подряд вход закрывается на 15 минут —
это защита от подбора пароля, а не ошибка. Закрывается он **только для
того устройства, с которого ошибались**: если посторонний нашёл адрес
панели и подбирает пароль, вы всё это время заходите как обычно.

Если запрет достался вам самим и ждать не хочется — удалите через
файловый менеджер файл `dannye/popytki.json`. Он появляется сам и хранит
только счётчики, ничего важного там нет.

## Как поменять цену

1. Войдите в `/admin`.
2. Найдите блюдо — по категории или поиском в строке наверху.
3. Нажмите на строку с блюдом.
4. Поменяйте число в поле «Цена, ₽».
5. Нажмите **Сохранить**.

Цена меняется на сайте сразу — можно открыть страницу блюда в соседней
вкладке и убедиться.

### Зачёркнутая старая цена

Поле «Старая цена, ₽» — это цена, которая показывается зачёркнутой рядом
с новой. Так сделано у сетов.

- Чтобы показать зачёркнутую цену — впишите число, оно должно быть
  **больше** новой цены.
- Чтобы убрать зачёркнутую цену — оставьте поле пустым.

## Как добавить блюдо

1. В `/admin` нажмите **Добавить позицию**.
2. Впишите название — адрес страницы подставится сам, латиницей
   (например, «Сырники с ягодами» → `syrniki-s-yagodami`). Менять его
   вручную можно, но для уже существующих блюд лучше не трогать — на
   старый адрес могут вести чужие ссылки.
3. Выберите категорию из списка.
4. Заполните состав, вес, цену.
5. Отметьте метки, если нужны: «Хит», «Острое», «Детское», «Добавка».
6. При желании сразу загрузите фотографию (как — в следующем разделе).
7. Нажмите **Сохранить**.

Страница нового блюда появится сама, по подставленному адресу. Отдельно
никуда его добавлять не нужно — оно сразу попадёт и в каталог, и на
главную, если подходит под один из показанных там разделов.

**Если что-то заполнено неправильно** — например, не выбрана категория
или цена не число — панель покажет по-русски, что именно не так, и ничего
не сохранит. Сайт при этом продолжит работать в прежнем виде.

---

## Как удалить блюдо

Внизу формы редактирования — красная кнопка **Удалить**. Она приведёт на
страницу подтверждения: нужно нажать ещё раз, уже осознанно.

Если позиция входит в состав какого-то сета (например, ролл, который
перечислен в описании сета), панель это покажет отдельным предупреждением
и потребует дополнительной галочки — потому что после удаления состав
сета продолжит упоминать блюдо, которого больше нет в меню. В этом случае
после удаления стоит заглянуть в сет и поправить его состав вручную.

Удалённое меню не пропадает бесследно — перед каждым сохранением панель
делает резервную копию всего файла меню (раздел ниже).

---

## Как добавить или заменить фотографию

Прямо в форме блюда, поле «Выбрать файл»:

1. Нажмите на поле и выберите фотографию на телефоне или компьютере —
   JPEG, PNG или WebP.
2. Появится рамка для обрезки — квадратная, потому что на карточках
   в каталоге фото всегда квадратное. Подвиньте и растяните рамку так,
   чтобы в неё попало то, что должно быть видно.
3. Нажмите **Сохранить** внизу формы.

Сервер сам уменьшит снимок до нужных размеров и сохранит в современном
формате. Прежнее имя файла с телефона нигде не используется — снимок
всегда сохраняется под адресом блюда.

**Ограничение на размер файла** показано прямо над полем загрузки —
обычно несколько мегабайт. Если снимок с телефона больше, iPhone и
большинство Android-камер позволяют выбрать пожатие в настройках камеры
перед съёмкой, либо отправить фото через мессенджер самому себе — это
почти всегда уменьшает размер до подходящего.

Если сервер не смог опознать формат — например, это HEIC с айфона —
панель прямо это скажет и подскажет, как переключить формат съёмки на
JPEG в настройках камеры.

Если фотографии нет совсем — карточка покажет фирменную заглушку с
дудлом, ничего дополнительно делать не нужно.

---

## Резервные копии

Перед каждым сохранением любой позиции панель сохраняет копию всего
файла меню, каким он был до правки, в папку `dannye/kopii/` с меткой
времени в имени файла. Хранится 30 последних копий, более старые
удаляются сами.

Если что-то сохранилось не так, как хотелось, — попросите того, кто
выгружал сайт, вручную скопировать нужный файл из `dannye/kopii/` поверх
`dannye/menu.json` через файловый менеджер хостинга.

## Публикация на хостинге

Сайт выгружается на sweb обычной загрузкой файлов — по FTP или через
файловый менеджер в панели хостинга. GitHub здесь не участвует: это
инструмент для разработки и хранения истории правок, а не для показа
сайта посетителям.

Что выгружается — содержимое папки **`sayt/`** целиком, в подкаталог
`milk-site` на сервере (или в корень, если сайт должен открываться без
подкаталога — тогда нужно поправить `sayt/app/konfig.php` и
`sayt.config.mjs`: адрес записан в обоих, PHP не умеет читать конфиг на
JavaScript).

**Перед выгрузкой папку `sayt/` нужно собрать.** В репозитории её нет
целиком: картинки там не хранятся, потому что весят тридцать мегабайт и
получаются из `Referens/` командой. Полный порядок с чистой копии
репозитория:

```bash
npm install     # один раз
npm run images  # готовит картинки, кладёт их в том числе в sayt/images/
npm run sayt    # собирает стили, графику, шрифты и robots.txt для sayt/
npm run zip     # складывает всё в milk-site-sayt.zip для загрузки
```

Последняя команда собирает архив — заливать через файловый менеджер сотню
файлов по одному не нужно. Внутри архива лежит **содержимое** папки
`sayt/`, а не она сама: распаковывать его надо прямо в `milk-site` на
хостинге, папка внутри не создастся. Скрытые файлы `.htaccess` в архив
входят — без них не работает ни один адрес, кроме главной.

Шрифты качать не нужно: они лежат в репозитории, в `public/fonts/`, и
`npm run sayt` переносит их в `sayt/fonts/`. Обновить их до свежих версий
можно командой `npm run shrifty` — она сходит на Google Fonts и перепишет
папку; без интернета команда не нужна вовсе.

Только после этого `sayt/` полна и её можно заливать. Если выгрузить
папку без этого шага, сайт откроется, но будет без единой фотографии.

**При первой выгрузке** папка `sayt/dannye/` уже содержит меню — это
стартовая копия. Дальше она живёт только на сервере: правки через
`/admin` остаются там, а файл `menu.json` в корне репозитория на GitHub
их не увидит. Если понадобится перенести сайт на другой сервер —
скачайте актуальный `sayt/dannye/menu.json` с текущего сервера, не
берите его из репозитория.

**Карта сайта** для поисковиков собирается сама, отдельного файла для
неё выгружать не нужно: она доступна по адресу `/sitemap.xml` и
перечисляет главную, каталог и все страницы блюд по текущему меню. После
добавления или удаления блюда через `/admin` карта меняется сразу.

**Права на запись.** Панель `/admin` должна уметь писать в
`sayt/dannye/` (меню, резервные копии) и в `sayt/images/menu/`
(фотографии). На большинстве тарифов sweb это работает без
дополнительной настройки; если при сохранении появляется ошибка про
права доступа — обратитесь в поддержку хостинга с просьбой выставить
права на запись (обычно 755) на эти две папки.

## Что осталось заполнить

В вёрстке пометками `[ЗАПОЛНИТЬ]` отмечены места, куда нужны данные владельца:

- **стоимость доставки при заказе меньше 1200 ₽.** Сайт сейчас говорит только «при заказе от 1200 ₽ — бесплатно» и о цене ниже порога умалчивает. Если хотите её назвать — скажите сумму;
- **идентификатор Яндекс.Метрики**, если нужна аналитика. Место под счётчик готово в макете, сам счётчик не подключён;
- **проверить фразу «каждую готовим с утра»** в блоке про завтраки: если завтраки подаются только до определённого часа, текст надо поправить и подставить время.

Дату актуальности цен теперь можно поправить прямо в панели `/admin` —
поле наверху страницы со списком позиций, отдельно от самих блюд.

Координаты кафе владелец уже дал, они в `sayt/app/kafe.php`.

### Фотографии

- **Три позиции без снимка вовсе** — «Сет „Горячий“», «Калифорния с креветкой», «С креветкой темпура». Вместо фото стоит фирменная заглушка — или загрузите снимок через `/admin`;
- **десять кадров на пересъёмку** — чужая съёмка на чёрном и чисто-белом фоне, список в `TZ-prilozhenie-foto.md`, печатает `node scripts/otchet-fon.mjs`. Загрузку через `/admin` можно использовать и для них — панель обрежет и сожмёт снимок, но не выполняет автоматическую нормализацию фона, которую делает конвейер на Node (раздел для разработчика ниже).

## Для разработчика

Два разных слоя, и важно не путать их при правке.

**Дизайн** — на Astro, исходники в `src/`. Здесь правятся стили, шрифты,
цвета, форма дудлов и блобов, вёрстка компонентов.

**Публикация** — на PHP, исходники в `sayt/`. Страницы каталога, блюда и
главная собираются здесь заново при каждом открытии, читая
`sayt/dannye/menu.json`. Стили и графика сюда не пишутся руками — их
экспортирует команда `npm run sayt` из `src/`.

```bash
npm install            # установка зависимостей
npm run images          # готовит public/images/ из Referens/ и попутно sayt/images/
npm run dev              # локальный сервер разработки дизайна (Astro)
npm run build             # сборка Astro-версии — используется для сверки при изменении дизайна
npm run shrifty             # скачивает шрифты Rubik и Onest в public/fonts (нужен интернет)
npm run zip                 # собирает milk-site-sayt.zip из готовой папки sayt/
npm run sayt               # пересобирает sayt/statika/sayt.css и sayt/app/grafika.php из src/
npm run sayt:server         # локальный сервер PHP-версии, та же подпапка /milk-site, что на хостинге
npm run check:menu           # проверка menu.json без сборки
npm run check:php             # обходит все 97 адресов PHP-версии, требует чистый sayt/dannye/oshibki.log
npm run check:verstka          # прокрутка и выход элементов за границы на всех ширинах
npm run check:seo               # заголовки, описания, alt, микроразметка
npm run check:fon                # читаемость текста на фоне первого экрана
npm run check                     # три проверки подряд
```

Проверкам нужен браузер: `npx playwright install chromium` один раз. Если
браузер уже стоит где-то отдельно, путь к нему задаётся переменной —
`BRAUZER_PUT=/путь/к/chrome npm run check`.

Проверки вёрстки, SEO и фона принимают адрес вторым аргументом и одинаково
работают что против Astro-версии (`npm run preview`), что против
PHP-версии (`npm run sayt:server`):

```bash
node scripts/proverka-vyorstki.mjs http://127.0.0.1:8080/milk-site
```

Шрифты Rubik и Onest лежат рядом с сайтом, а не тянутся с Google Fonts:
оттуда они шли неровно, а при недоступности страница меняла вид на
системный шрифт. Оба вариативные, поэтому файл один на подмножество, а
вес в `@font-face` задан диапазоном. Подмножеств три — `latin`,
`latin-ext`, `cyrillic`; `latin-ext` нужен не для европейских языков, а
ради знака рубля U+20BD, который лежит именно там. Лицензия SIL Open Font
License, её текст выгружается вместе со шрифтами (`LICENSE-*.txt`).

Стек публикации: PHP 8.2+, встроенный GD для обработки фото в админке,
обычный CSS с переменными в `src/styles/tokens.css` — единственном месте
с цветами и размерами для обоих слоёв.

Папка `Referens/` — исходные материалы, только для чтения. Обработанные
изображения складываются в `public/images/` и `sayt/images/`, в репозиторий
не коммитятся: пересобираются командой `npm run images`.

Устройство админки — в `sayt/admin/`: `app/dostup.php` отвечает за вход и
хранение пароля, `app/hranenie.php` — за проверку данных и запись меню
через временный файл с переименованием, `app/foto.php` — за приём и
обрезку фотографий. Подробности реализации — в комментариях этих файлов.
